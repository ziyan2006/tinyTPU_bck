警告为什么保留？
原 MMU testbench 用 to_signed(value, 8) 编码部分大于 127 的无符号数据，GHDL 因此报告 vector truncated；以无符号模式进入 MMU 后，16 个输出比较仍通过。同步 RAM 的未初始化数据在启动 / 排空阶段还会触发 numeric_std 的未知值警告。本次保留这些警告与 error 级停止检查，最终只认可实际断言和成功报告。
GHDL 采用 VHDL-2008；-frelaxed-rules 用于仓库现有共享变量双口 RAM 模型。没有验证严格模式下的原 RAM 模型。


真实轨迹如何采样与核对？
MMU VCD 不直接输出 BYTE_ARRAY / WORD_ARRAY。生成器采集 16 个 MACC 的标量寄存器，按 RESULT_ASSIGNMENT 从末行 21 位部分和及符号移位寄存器重建输出；核对两组共 32 个预期元素，保留全部 38 个上升沿。
完整 TPU testbench 增加仅用于观察的 112 位主机输入 / 权重 / 输出总线镜像；系统生成器核对实际读回总线、392 个独立数学预期值与自检日志。保留 252 个连续上升沿、8 条实际入队指令及执行控制使能。输入 / 控制采沿前值，寄存器 / 主机输出采沿后稳定值；日志检查发生在沿后 1 ns，页面到达报告之后才显示已核对结果。
10 ns 为 testbench 时钟，不代表综合后频率。完整 TPU 轨迹走直接主机端口，框图的 AXI 保持无高亮；AXI 回归有独立日志和自检，不在此时间轴假造握手或 IRQ 波形。原始 system.vcd 在交付包中。
